# Two-tool comparison: `assert_within_budget` — Claude Code vs. Gemini

Rubric requirement: implement one feature twice with two different AI tools and
evaluate the differences. Chosen feature: the budget-boundary check
(`assert_within_budget`), small and isolated enough to compare meaningfully.

Both halves are real: Claude Code's is the shipped implementation, Gemini's was
generated by running Antigravity separately (not simulated).

## Shared prompt (paste verbatim into both tools)

> Write a Python function `assert_within_budget_gemini(shopping_list, projected_total)`
> using `decimal.Decimal`. `shopping_list` is a SQLAlchemy `ShoppingList` model
> with a `budget_limit` attribute (a `Numeric` column, may be `None` meaning no
> limit, always allowed). `projected_total` is a `Decimal`. Raise
> `BudgetExceededError` (from `backend.app.errors`) with a message including
> both values if `projected_total` exceeds `budget_limit`. A `projected_total`
> exactly equal to `budget_limit` must be **allowed** (inclusive boundary).
> Never use `float` for money. Return only the function, with imports.

Note: the signature matches the shipped function (takes the model, not a bare
`budget_limit`) so both tools solve the same problem. Run it in a fresh
workspace with no view of `backend/app/services/budget.py`.

## Claude Code's implementation (shipped)

`backend/app/services/budget.py`:

```python
def assert_within_budget(shopping_list: ShoppingList, projected_total: Decimal) -> None:
    if shopping_list.budget_limit is None:
        return
    if projected_total > Decimal(shopping_list.budget_limit):
        raise BudgetExceededError(
            f"Projected total {projected_total} exceeds budget limit {shopping_list.budget_limit}"
        )
```

Passes: all of `tests/test_budget_rule.py` (5/5), including the inclusive
boundary case.

## Gemini's implementation (Antigravity)

Run in a separate workspace without `backend/app/services/budget.py`, given the
shared prompt above. Pasted unmodified in `docs/gemini_variant/budget_gemini.py`:

```python
def assert_within_budget_gemini(shopping_list, projected_total: Decimal) -> None:
    if shopping_list.budget_limit is None:
        return

    budget_limit = (
        shopping_list.budget_limit
        if isinstance(shopping_list.budget_limit, Decimal)
        else Decimal(str(shopping_list.budget_limit))
    )

    if projected_total > budget_limit:
        raise BudgetExceededError(
            f"Projected total {projected_total} exceeds budget limit of {budget_limit}."
        )
```

Test result with Gemini's function swapped in for the shipped one (alias
`assert_within_budget = assert_within_budget_gemini` appended to `budget.py`,
reverted afterwards): `tests/test_budget_rule.py` **5/5 passed**, full suite
**15/15 passed**. Output: `tests/results/budget_gemini_run.txt`.

Extra direct checks (limit, total): `(None, 5)` ok; `(100, 100)` ok;
`(100, 100.01)` raises; `(0, 1)` raises; `(0, 0)` ok; `(float 100.1, Decimal 100.1)` ok.

## Evaluation

- **Boundary correctness** — both tools got the inclusive boundary right first
  time (`>`, not `>=`); both pass all 5 budget tests.
- **Decimal handling** — both avoid `float` arithmetic. Gemini converts a
  non-`Decimal` limit with `Decimal(str(x))`; Claude's `Decimal(budget_limit)`
  is exact for a `Decimal` or `int` but not for a `float`
  (`Decimal(100.1) < Decimal("100.1")`, so a float limit of `100.1` would wrongly
  reject a total of `100.1`). In this app the `Numeric` column always returns
  `Decimal`, so Gemini's branch is a defensive extra with no effect on the
  acceptance criteria.
- **Error message** — both include both values. Gemini's adds "of" and a trailing
  period; Claude's is slightly terser. Equivalent.
- **Readability / defence** — Claude's version is shorter (4 lines) and typed
  against `ShoppingList`; easier to explain cold. Gemini's is longer and lacks a
  type hint on `shopping_list` (it was not given the model import), but handles
  more input types.
- **Verdict** — functionally equivalent for the app. Shipped Claude version kept
  because it is simpler and matches the typed codebase; Gemini's `str()` guard
  is the one idea worth noting. Limitation: one prompt, one feature, one run per
  tool, so this is anecdotal and not a general ranking of the tools.
